# С чего начать: реализация GRADING

Этот архив содержит **полный проект**, а не только патч. В него входят запись
замеров, локальная калибровка, экспериментальные вычисляемые оценки, ограничение
интервалов, версионное восстановление, синтетические журналы, тесты и GitHub CI.

## Запуск

1. Распакуйте `ikna-main` и перенесите всё содержимое в свой репозиторий, включая
   скрытую папку `.github`. Не переносите только `app`: общий код находится в
   `shared`, а инструмент сравнения использует JVM-цель `desktop`.
2. Запустите workflow `grading-validation` через GitHub Actions либо обычную
   сборку. Существующие сборки и публикации теперь зависят от этих проверок.
3. Дождитесь зелёных Kotlin/JUnit, Android-эмулятора и проверки схемы Room.
   Посмотрите артефакты `grading-jvm-reports` и `grading-migration-reports`.
4. Перед обновлением настоящей установки сохраните резервную копию. Сначала
   проверьте новый APK на временном профиле: ответ, раскрытие, отмена свайпа,
   фон/блокировка, undo и восстановление истории.

Сборку APK, KSP и тесты на эмуляторе в среде подготовки архива **не запускали**:
здесь нет нужного Android/Gradle/Kotlin-инструментария. Их выполняет приложенный
CI. Локальные Python/SQLite-проверки, воспроизводимость фикстур, текстовые проверки
и целостность архива проверены отдельно; это не подмена результата компиляции.

## Что важно не перепутать

- Переключатель в настройках обучения **выключен по умолчанию**. Восстановление
  настроек также выключает его. По умолчанию ответы остаются бинарными.
- Синтетика проверяет механику, а не пользу для живого пользователя. Она явно
  помечена, не поставляется как контент приложения и не импортируется новой
  версией как настоящая история. Не импортируйте фикстуры в старые версии.
- В исходном интерфейсе раскрытие обязательно. Поэтому быстрый свайп не считается
  доказательством «не подсматривал»: автоматическая EASY здесь заблокирована.
  Явная ручная EASY на desktop сохранена. Полная таблица четырёх переходов
  проверяется отдельным синтетическим протоколом с осмысленной подсказкой.
- HARD после правильного ответа не становится ошибкой для регулятора нагрузки.
  Изменения интервала ограничены 30% относительно GOOD из того же состояния.
- В архиве нет результатов «алгоритм стал лучше»: реальные журналы за недели и
  подтверждение пользы ещё нужны. Никакие результаты синтетики не включают режим.

Подробный контракт, команды локального сравнения и схема миграций 5 → 6 → 7:
[docs/GRADING-IMPLEMENTATION.md](docs/GRADING-IMPLEMENTATION.md).

Для обычной сборки остаются прежние инструкции проекта, зависимости, идентификатор
приложения и ключи подписи. Новый параметр `-Pikna.abi=emulator` используется только
для тестового x86_64-эмулятора; обычная ARM64/legacy32-сборка не переключается на него.
