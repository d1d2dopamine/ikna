# Round 61 — выпускная сборка desktop

## Причина

Сообщение upload-artifact о пустом desktop/build/compose/binaries/main-release/nsis/*.exe — вторичное. В обоих приложенных логах Windows и Linux раньше падает :desktop:proguardReleaseJars: 136 ссылок на 28 отсутствующих типов из 20 классов. До создания установщика выполнение не доходит. Путь загрузки не изменяется, if-no-files-found: error сохраняется.

Не найдены необязательные Android API, альтернативные TLS-провайдеры и зависимости неиспользуемых Tink HTTP/HPKE-реализаций. В показанных предупреждениях нет отсутствующего класса приложения, JDK или protobuf. Это подтверждено разбором обоих полных логов; конкретные имена/счётчики сохранены в INPUT-DIAGNOSIS.json.

## Связь с загруженным коммитом

Официальный API GitHub показывает run 39135025333, commit 620cfc770200db8ccf97342873c06cee96877aca. Время двух desktop-ошибок соответствует приложенным логам. На этом коммите desktop/compose-desktop.pro, desktop/build.gradle.kts, shared/build.gradle.kts и .github/workflows/build.yml побайтово совпадают с переданным Round60. Следовательно, для этих четырёх значимых файлов проблема уже была в выданных исходниках, а не возникла при переносе в GitHub. Это не общая сертификация программы загрузки коммитов.

В том же запуске проверки grading/migrations, grading/JVM и Android завершились успешно. Это факт старого запуска, не результаты проверки исправленного Round61.

## Ограничения среды

Восстановлен Gradle8.10.2 с официальным SHA-256 и Microsoft OpenJDK17.0.20.1 с опубликованным SHA-256. API другого поставщика JDK вернул403, его доступ не обходился. Полный локальный Gradle-запуск остановился ещё на разрешении Android Gradle plugin8.6.1, до компиляции. Этот сбой не выдаётся за успешную сборку и не доказывает проблему исправленного исходного кода.

## Исправление и фактические проверки

В desktop/compose-desktop.pro добавлены исключения только для 20 точных ссылающихся классов необязательных путей. Не добавлялись -ignorewarnings, запрет shrinking или широкое подавление всех okhttp3/com.google.crypto. Версии зависимостей, Kotlin-код приложения, установщик и его строгая проверка наличия не менялись.

Новый tools/test_desktop_proguard.py включён в существующий Python-шаг CI. Его два быстрых теста проверяют точную границу исключений и привязку к используемым зависимостям/API. Дополнительный режим реально компилирует и обрабатывает библиотечный Java-стенд. Выполнено:

- Старые правила: точно воспроизведены 136 отсутствующих ссылок, 28 типов, 20 владельцев; ожидаемый отказ ProGuard.
- Исправленные правила: ProGuard7.7.0 успешно уменьшил стенд с закреплёнными Tink1.23.0 и OkHttp4.12.0; отсутствующих ссылок нет.
- Полученный JAR успешно выполнил генерацию сертификата/PEM, TLS между двумя loopback-сокетами в одном процессе с проверкой точного сертификата, XChaCha20Poly1305 keyset/encrypt/decrypt и отказ при повреждении шифротекста.
- Два отрицательных сценария с тем же отсутствующим типом из нового класса приложения и нового класса платформы по-прежнему завершились отказом. Это проверяет, что новая ошибка зависимости не скрывается исключением по целому пакету.
- Точные 13 команд текущего Python-шагa grading.yml завершились с кодом0, включая прежние проверки и новый checker. Два статических теста входят в этот шаг и не прибавляются второй раз как уникальное покрытие.

Стенд использует defaults из реального Compose-плагина1.8.2 и текущие production-правила. Отсутствие обфускации соответствует реальному значению по умолчанию ProguardSettings этого плагина; bytecode проверен независимо, в проекте переопределения нет. Это не ослабление конфигурации ради теста.

Исходники теста, команды/хеши зависимостей, диагностические результаты и журналы сохраняются с исправлением. Независимая проверка подтвердила точность исключений и результаты положительного/отрицательных запусков.

 Успех такой проверки не заменяет Windows NSIS/установку или целый Compose release. Для окончательного закрытия нужен обычный новый CI-запуск владельца на исправленном коммите; автоматический dispatch и публикация здесь не выполнялись.
