## 2. Инвентаризация прямых углов (Track J, скруглённый вариант)

Ключевой факт: **ни один composable не читает `MaterialTheme.shapes`** —
`IknaShapes` (все `RoundedCornerShape(0.dp)`) объявлен в `Theme.kt`, но не
потребляется. Ненулевых `RoundedCornerShape/CornerRadius` в коде нет вообще —
кроме параметрических радиусов Signal Frame (`cornerRadius = 6–8.dp`), то есть
скругления сегодня есть только у самой рамки. `clipToBounds` — одно место
(`DeckList.kt:150`).

Что придётся решить варианту 2 (по группам):

| Группа | Места | Решение |
| --- | --- | --- |
| Форма-система | `Theme.kt` `IknaShapes` | завести `IknaShapeVariant` (angular/rounded) и радиусы по классам (чипы/поля/карточки/панели) |
| Границы контейнеров | `Flat.kt` чипы (560), кнопки (352), поля (602, 640), тумблер (490); `DeckList.kt` строка; `PaletteTiles.kt` плитки; `BrowseCard.kt` блоки | радиус границы из варианта; сейчас все `.border(1.dp …)` квадратные |
| Canvas-примитивы | `MemoryLattice.kt` (зерно — **оставить квадратным**: пиксельный язык), `IknaProgress` (ячейки), `SignalFrame.kt` (рамка уже скруглена параметром), `WindowTitleBar.kt` иконки окна (штрихи) | решётка и прогресс — квадрат при обоих вариантах; кнопки окна — радиус по варианту |
| Карточка сессии | `CardStack.kt`, `BrowseCard.kt` блоки | радиус карточки — самое видимое отличие вариантов |
| Печати/метки | `DeckMark` 52dp, `EN`-печати | печатный квадрат — маркер идентичности; решать отдельно (возможно, квадрат при обоих вариантах) |

Риск forks-кода отсутствует: точек вариации мало, все через `IknaShapes`/

## 3. a11y-обход

- **`IknaIconButton`:** все реальные call-site'ы передают `label` ✓ (единственное
  «срабатывание» grep'а — определение самой функции в `Flat.kt:246-253`).
- **`clickable` без `role`:** `DeckList.kt:83,151`, `BrowseCard.kt:104`,
  `CardStack.kt:441,528`, `TransientNotice.kt:45` — добавить `role` и/или
  `onClickLabel`; `PaletteTiles.kt` (Role.RadioButton ✓) и `Flat.kt` (Role.Button ✓)
  — образцы. `StatsContent.kt:114` уже с `onClickLabel` ✓.
- **a11y-ключи:** определены `a11y.001–012, 014, 015` — **в нумерации нет
  `a11y.013`** (когда-то удалён?). Проверку «ключ определён, но не
  используется» не удалось завершить из-за регэксп-ошибки скрипта — доделать
  при G-работе (все ключи выглядят потреблёнными: 001 back, 006 toggle,
  007 stats-open, 010/012/015 deck icons).
- **Декоративные Canvas** (`IknaMemoryField`, `IknaMemoryAmbientStrip`,
  `IknaDeckHeaderPaint`, `IknaProgress`, wordmark): `clearAndSetSemantics`
  нигде не стоит; Canvas без семантики скринридеры обычно игнорируют, но
  явный `invisibleToUser` на декоративных поверхностях — дешёвая страховка
  (особенно для новых полос с анимацией).
- **Строки с вложенными кнопками** (`IknaDeckRow`: две иконки + тумблер внутри
  кликабельной строки): проверить mergeDescendants, чтобы TalkBack не читал
  строку как один комок — кандидат в G-11.

### Архитектура доставки

`IknaShapes` (Theme.kt) сегодня не потребляется ни одним composable — это
свободная точка входа. План доставки:

1. `enum class IknaAppearanceVariant { ANGULAR, ROUNDED }` + CompositionLocal
   из IknaTheme; хелперы `iknaControlShape() / iknaCardShape() / iknaTileShape()`,
   возвращающие `RoundedCornerShape(0.dp)` или радиус по варианту.
2. `MaterialTheme.shapes` подключается к тем же значениям (для будущих M3
   компонентов), чтобы вариант был единственным источником формы.
3. Все 22 сайта `.border(...)` получают shape-параметр (border умеет shape);
   hover-заливки кнопок окна и чипов клипаются тем же shape.
4. Хранение выбора: настройка в «Внешнем виде» (новые ключи во всех 7 языках)
   либо эксперимент-флаг — вопрос владельцу.
5. parity-тест дополняется контрактом варианта (как уже сделано для фокуса).

### Радиус-система (предложение владельцу на утверждение)

контролы/чипы/поля/заметки — 10dp; плитки — 12dp; блоки и панели — 14dp;
тумблер-трек — пилюля 16dp; кнопки окна — 8dp; квадратные сигнатуры (решётка,
ячейки прогресса, печати, вордмарк) — не меняются ни при каком варианте.

### Риски

- 22 border-сайта + focused-варианты (2dp) — механическая, но широкая правка;
  parity-тест удержит от пропусков.
- hover-заливки без клипа будут «выступать» за скруглённую рамку — каждому
  кликабельному контейнеру нужен `clip(shape)`.
- Окно Windows 11: DWM может скруглять углы окна сам — проверить на живом
  запуске, как это выглядит с кастомным тайтл-баром.
- Строки настройки варианта — 7 языков; где живёт переключатель — решение
  владельца (Внешний вид vs скрытый эксперимент).
